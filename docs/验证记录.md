## 验证边界

jsdom 不提供实际浏览器布局，测试中以接口替身检查剪贴板调用。因此，上述通过结果只证明转换和交互逻辑在相应条件下符合断言，不证明样式在所有浏览器或公众号中保持一致。

此前尝试运行 Playwright 浏览器验收：项目包没有预装 Playwright Chromium；改用系统 Chrome 后，headless 子进程启动即以 `SIGABRT` 退出，未能进入页面检查。先前在此受限环境启动本地静态服务器监听也遇到过 `EPERM`。因此没有生成浏览器截图，未验证真实布局或操作系统剪贴板。1.1.0 又尝试启动工作目录中的 Chromium headless shell，浏览器同样在启动阶段关闭，未进入页面。因此新版也未取得真实布局或截图证据。`tools/browser-check.cjs` 已增加隐藏滚动条后的滚动能力、大纲定位、段落间距、图注和手机跳转检查，可在普通本机环境执行补验。

用户已反馈旧版在公众号粘贴时出现列表分行、参数缩进和参考链接问题。本次按这些反馈修改；开发助手未登录微信公众号，尚未取得新版在微信 PC / 手机客户端的复测结果，也未提交或发布文章。未进行真实 TRAE 开发操作，未创建 GitHub 仓库和 Pages 地址。相应步骤见 [截图与公众号验收](截图与公众号验收.md)，复测素材为 [公众号粘贴回归样例](公众号粘贴回归样例.md)。

## 复现

在普通本机终端安装 Node.js 24.15 或更新版本，然后在项目根目录执行：

```sh
npm ci
npm run check
npm test
npm run example
npx playwright install chromium
npm run test:browser
```

本次测试依赖通过工作目录中的独立开发环境提供，项目包不含 `node_modules`；分发包以 `package-lock.json` 锁定重新安装所需依赖。网页运行完全不依赖测试包。
